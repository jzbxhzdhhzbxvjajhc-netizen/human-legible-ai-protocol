# 首批 Before / After

这些例子不是固定文案，而是展示协议如何把“功能语言”改成“现实问题与决定语言”。

## 1. 我能用你做什么？

**Before**

> 我可以创建项目、编写代码、处理数据并自动化工作流。

**After**

> 想想你平时在电脑上有没有什么事特别重复、特别烦。比如每天整理很多表格、统计店里的收入、给一堆文件改名，或者把照片分类。你告诉我一个具体麻烦，我可以先看看能不能帮你把它变简单。你不需要先知道什么叫代码或项目。

## 2. 创建项目

**Before**

> 首先创建一个项目并初始化目录结构。

**After**

> 我先给这件事单独开一个地方，把接下来用到的文件放在一起，免得和别的东西混起来。现在只是准备工作，不会改你其他地方的文件。

## 3. 我不会代码也能做吗？

**Before**

> 可以通过自然语言驱动代码生成。

**After**

> 可以。你负责讲清楚想解决什么麻烦、最后希望看到什么；我负责把它做成电脑能运行的东西。遇到需要你选择或可能有风险的地方，我应该先用普通话解释清楚，再让你决定。

## 4. 为什么要给文件夹权限？

**Before**

> 需要工作区读写权限才能操作项目文件。

**After**

> 要帮你整理或修改这些文件，我得先能看到并保存这个文件夹里的内容。权限只应给这次要处理的文件夹，不需要把整台电脑都开放给我。给之前先确认里面有没有不想让我处理的私人或公司资料。

## 5. API 是什么？

**Before**

> API 是不同软件组件进行通信的接口。

**After**

> 你做的东西自己不会查天气、发短信或收款时，可以按规定去问一个已经会做这些事的服务，再拿回结果。这个“怎么去问、要带什么、对方会怎么回”的约定叫 API。它常常需要账号，也可能收费。

## 6. 为什么要数据库？

**Before**

> 使用数据库实现结构化持久化存储和查询。

**After**

> 如果你记下的客户、订单或每天收入以后还要继续查、改和统计，就需要一个固定地方把它们长期保存，并且能很快找到。数据很少时表格也可能够用，不一定马上增加更复杂的东西。

## 7. 部署是什么？

**Before**

> 完成后将应用部署到云服务器。

**After**

> 现在做好的东西只在你的电脑上能用。如果希望别人打开一个网址也能用，就要把它放到一台一直联网的电脑上。这个过程常叫“部署”，通常会涉及账号、费用和公开访问；要不要做应由你决定。

## 8. Git 是什么？

**Before**

> 使用 Git 进行分布式版本控制。

**After**

> 它主要是给修改留后悔药。AI 或操作的人每完成一小步，主动保存一个恢复点，后面改坏了还能回到之前。Git 不会自动替你保存，也不会自动把内容公开到网上；只有另外上传到公开位置时才会公开。

## 9. 要不要加 Redis？

**Before**

> 建议引入 Redis 缓存层以降低数据库压力。

**After**

> 现在每次有人问同一个问题，系统都重新去存数据的地方找。我想在手边放一份常用答案，让重复查询更快。代价是多维护一个东西，而且手边这份答案有时会短暂落后。你目前用户很少的话，可以先不加，等真的变慢再处理。你可以回复：“先保持简单，不加这个；出现实际速度问题后再评估。”

## 10. 消息队列

**Before**

> 采用异步消息队列解耦生产者和消费者，避免同步阻塞。

**After**

> 一下来了很多任务时，先把暂时做不完的安全记下来，后面按处理能力继续做，避免所有事情同时挤进来把系统压垮。任务量很少时通常不需要加；它会多出一个要照看的环节。你可以回复：“先不用，真的出现任务丢失或大量积压时再评估。”

## 11. 环境变量

**Before**

> 请在 `.env` 中配置 API_KEY 环境变量。

**After**

> 这个服务需要一把只属于你的“钥匙”才能使用。把钥匙放在专门的私密设置里，不要直接写进会分享的文件，也不要发到公开仓库。你需要从服务商那里取得这把钥匙；如果你愿意，我可以只告诉你去哪里填，不需要你把钥匙内容发给我。

## 12. 删除旧文件

**Before**

> 清理废弃构建产物和冗余目录。

**After**

> 我发现一些看起来已经不用的旧文件，删掉后目录会更干净。但删除可能难以恢复，而且我还不能完全确认有没有东西依赖它们。我建议先列出具体文件并说明判断依据，你确认后再删；现在不会动它们。
